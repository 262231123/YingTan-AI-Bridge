# 轴网定位与设备钢平台（0.6.0 预览版）

## 使用方式

关闭 Revit，安装新版 EXE 后重新打开项目和助手，建议新建对话。需要当前项目已经加载结构材料分类为 Steel 的柱、梁族及适用的楼板类型。

输入例如：

> 我想在 K-H轴/36-37轴区域内，布置一个设备钢结构平台，两侧操作平台高度为1m，宽度为2m，中间设备平台高度为2m。尽可能减少立柱数量和梁高。请先读取轴网、标高和可用结构类型，再问我缺失的设计条件，比较方案后建模。

助手会读取真实轴线交点、轴距、标高和已加载类型，不应要求你手动提供已经能从模型读取的轴距。优先当前模型；也可读取已加载链接并变换到当前模型坐标。多个链接有同名轴网时，需要确认具体链接。

仍须由你确认模型无法表达的设计意图：设备区域长宽、两侧平台沿哪组轴线、1m/2m相对于哪个标高、柱底高度、荷载和支承方式、梁高上限等。已提供的条件应保留，无需每轮重复输入。荷载暂时没有时，可以明确回答“荷载待定，仅做概念布置”，但这不意味着结构安全已经确认。

补齐条件后生成纵向1/2/3跨候选方案，分别比较柱数、跨度及所选梁高。你可以回复“选择方案一”。查询结果和方案编号会保留在当前文档的会话内；预览30分钟失效，重启或轴网/标高/类型变化后必须重新预览。

- 默认：真实族试建、顶高检查并回滚通过后，点击“执行计划”。
- 可选：勾选“自动创建设备平台（试建通过后执行）”。这是对本对话单个平台计划的执行授权，缺失条件仍会询问；仅一个 `create_steel_platform` 操作可自动执行，其他修改仍需审阅。切换对话会取消勾选。
- 实际创建后回读构件。试建失败会返回实际错误，不生成可执行计划。成功试建不保留临时构件，也不返回失效的临时构件ID。

## 建模范围与限制

支持直线、正交的四轴区域，可旋转、平移，也支持经链接变换的轴网。平台矩形居中布置，必须容纳在轴网区域内；弧轴、斜交轴网不做近似处理。

创建独立柱、纵横梁、两侧低平台板和中间高设备平台板。柱数按四排支点乘以纵向站点数计算，1/2/3跨分别为8/12/16根柱，内侧柱共用。板顶按用户指定高度，梁顶位于板底；真实几何顶高偏差超过5mm则回滚，特殊族可能因此需要调整或替换。

**这是几何概念建模，不是结构优化计算。** 荷载仅记录，未接入强度、挠度、稳定、抗震或基础承载力验算。少柱与低梁通常存在冲突；增加纵向柱不一定减小设备带横向梁跨度。软件不会宣称某个截面已经安全或是全局最优。应由合格结构工程师完成验算后再用于施工。

本版不自动生成基础、连接节点、支撑、楼梯、栏杆，也不支持依附既有结构的连接设计。邻近构件只是当前模型包围盒粗筛，非精确碰撞检查，不覆盖链接构件碰撞。楼板材质/构造以你确认的真实类型为准；不会自动下载族或把混凝土柱梁当作钢构件。

## 新增命令

| 命令 | 功能 |
| --- | --- |
| `list_grids` | 列出当前模型及已加载链接的轴线名称 |
| `resolve_grid_region` | 求四轴交点、尺寸与方向 |
| `list_structure_types` | 分页读取真实柱、梁、板类型及梁高 |
| `preview_steel_platform` | 校验输入、生成三个概念方案及有效预览ID |
| `create_steel_platform` | 仅从有效预览创建；dry-run为真实试建后回滚 |

“轴网定位与设备钢平台”内置 Skill 会随默认技能合并加入，保留用户已有技能设置。

## 验证范围

插件使用本机 Revit 2026.5 API（.NET 10）编译。便携回归覆盖轴名提取、倒向/旋转轴线、尺寸边界、分跨柱数、平台高度、自动执行边界和跨轮查询保存。GitHub CI执行便携测试；本机应用程序控制策略阻止测试程序执行，不修改系统策略。

尚未在真实 Revit 项目内完成端到端 AI 调用、真实族试建/提交或安装器交互验收。请在项目副本中试用；安装包未签名，其他 Revit 小版本未验证。

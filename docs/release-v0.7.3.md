# v0.7.3-preview

修复对话式建模在只读预览环节卡住的问题。

## 原因

模型有时会在 `reply` 中写“现在调用预览”，同时返回 `plan: null`。`reply` 只用于显示，宿主不会从自然语言猜测并执行命令，因此实际没有调用 `preview_steel_platform`，也不会产生 `previewId`。

## 修复

- 运行循环会识别“现在、先、接下来、准备查询/预览/执行”等立即行动承诺。
- 如果行动承诺对应的是空计划，宿主不会把它当作已执行结果，而会在同一轮向模型返回协议错误。
- 参数已经明确时，模型必须立即补交包含完整参数的实际计划；确实缺少参数时只能询问缺失项。
- 钢平台预览执行后，真实 `previewId` 和 1/2/3 跨结果会返回规划器；用户已选方案时可继续生成写入计划。
- 系统提示明确规定：`reply` 永不触发命令，不能承诺“稍后自动执行”。

本修复不绕过写入确认。预览为只读；实际创建仍需在待执行计划中点击“执行计划”。
